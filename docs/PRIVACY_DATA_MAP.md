## Browser storage audit

- Cookie: `ht_demo_session`, strictly necessary, random opaque value, `HttpOnly`,
  `SameSite=Lax`, `Secure` in production, path `/api/v1`, expiry aligned to the
  configured workspace TTL.
- `localStorage`: none.
- Kennel Map Move Together previews and Undo history exist only in component memory.
  Drop, selection, Undo, and review cancellation send no move payload. Only explicit
  confirmation sends the existing workspace-scoped batch; drafts and preconditions
  are never written to browser storage, URLs, or logs. Leaving/reloading discards them.
- `sessionStorage`: none.
- IndexedDB: none.
- Analytics, advertising, marketing, and fingerprinting identifiers: none.

Housing read/write uses the existing session cookie; it introduces no new browser
identifier or storage. A response-only HMAC precondition binds a pending housing
request to its workspace, demo date, and revision. It is not a session credential,
is not placed in URLs, and must not be logged with request bodies or cookie values.
Missing or expired cookies on the Map GET return baseline without creating a workspace.

The cookie is not a consent mechanism or marketing identifier. No consent banner is
shown because the only browser storage is required to isolate the interactive demo.
This decision must be revisited if non-essential storage is introduced.

## P14A/P14B boundary — optional server-side synthetic-data review

P14A introduced no live transport or public endpoint; that historical restriction
remains true for A. P14B adds an explicit default-disabled selected-day review and
bounded transport, without enabling or publishing it in production. Fake/offline
integration and UI acceptance do not prove live inference or account privacy controls.
The public Privacy section is conditional on runtime `operations_review_enabled`;
disabled production must not imply Groq/OpenRouter processing is already active.

Only the explicit review click can send bounded synthetic fields to the server's
configured providers. Excluded fields include free-text plan/activity/dog notes and
labels, Contact messages, visitor details/IP/client headers, cookies, HMAC/preconditions,
internal workspace IDs, API keys, database URLs, images/PDFs and complete histories.
The server's network connection is visible to its provider; visitor identity is not
forwarded. Provider/model/tool/count/error metadata is allowlisted; no raw prompts,
responses, hidden reasoning, keys or session values enter logs/review artifacts.

The UI explains external processing before the first action and distinguishes model
text from checked facts. Date/session/Reset/navigation/expiry/Cancel invalidate results;
cancellation cannot promise remote generation cancellation or quota return. It creates
no additional cookie, consent banner, analytics or browser store. The capability GET
and Privacy GET never initialize a workspace. Review requires an existing valid cookie
and same-origin request; its response is no-store.

Historical limited live campaigns are CLOSED at cumulative 21/21. P14C recovery was
independently accepted at `0b602970df7d2b0263b055abcf5b462626ba2f08` in Groq-only
demo scope with three required genuine results. P14D is local presentation/Privacy
review only, with no new inference or provider metadata calls. Accepted live results
do not prove universal prose correctness, future Free availability or account-level
retention guarantees. Exact history is in `OPERATIONS_AGENT_FOUNDATION.md`.

Reset removes mutable workspace rows (including notes/housing changes), not its cookie,
and does not extend the existing server expiry. The public notice uses runtime TTL
metadata rather than a fixed-duration promise.


## P14D portrait and notice revision

The profile viewer reuses the existing same-origin versioned synthetic WebP. Opening,
closing and zoom-in cursor presentation create no image-processing request, provider
image input, workspace mutation, recipient, analytics or browser store. Existing image
caching remains ordinary browser behavior. No new consent mechanism is added for this
viewer; reassess if non-essential storage or other processing is introduced.

The optional AI notice describes possible provider metadata/request retention instead
of instructing visitors to change operator account controls. Required disabled optional
logging/training settings remain operator requirements in `OPERATIONS_AGENT_FOUNDATION.md`.
P14D reuses earlier owner attestation; it does not assert a fresh ZDR-account inspection.
The candidate notice date is 2026-11-22 in settings/templates; confirm the actual effective
date when publishing. Production environment and real controller/contact/hosting/mail/
TTL values are untouched by this local package.
