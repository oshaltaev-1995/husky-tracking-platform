# Privacy data map

This document describes the P11.5 public-demo processing boundary. It is technical
documentation, not a claim that deployment controls outside this repository already
exist.

| Activity | Data and source | Purpose / legal-basis rationale | Application storage | Recipient/category | Retention / transfer |
|---|---|---|---|---|---|
| Contact form | Name, email, optional organisation, subject, message supplied by the visitor | Respond to the request; legitimate interest in communicating and, where applicable, requested pre-contract steps | Not persisted in PostgreSQL; passed to the configured delivery adapter | Local metadata-only sink, disabled adapter, or configured SMTP/mail provider | Mailbox/provider keeps delivered correspondence only as needed for inquiry follow-up and legal obligations. Provider region is configuration-dependent. |
| Demo session | Random opaque cookie generated by the backend; HMAC-SHA256 token digest under a runtime secret, creation and expiry timestamps in PostgreSQL | Isolate a functioning public demo; legitimate interest in safely operating the demonstration | `ht_demo_session` host-only HttpOnly cookie and `demo_workspaces`; no name, email, IP, fingerprint, or contact linkage | Application and configured hosting/database providers | 24 hours by default; server expiry is authoritative and `python -m app.demo.cleanup` deletes expired workspaces. Hosting region is production configuration. |
| Demo workspace edits | User-entered plan/activity notes, selected dogs, teams, and actual-work edits | Provide the interactive product workflow in an isolated workspace | Workspace-scoped `daily_plans` and `work_sessions`, with descendants; `demo_workspace_days` records copied dates | Application and configured hosting/database providers | Same workspace lifetime. Visitors are told not to enter real personal, confidential, customer, or health data. |
| Technical/security logs | Hosting/web-server IP, timestamp, requested path, user agent, correlation/error/security metadata | Reliable operation, troubleshooting, and abuse prevention; legitimate interest in operating and protecting the service | Not stored on `demo_workspaces`; application logs must exclude cookie/token values, note bodies, contact bodies, and credentials | Configured hosting/logging operators | Husky container logs have bounded Docker rotation (10 MiB × 3 per container); maintenance logs use the shared size-bounded systemd journal. No exact time-based deletion period is guaranteed. |
| Canonical demo data | Fictional dog names, pedigrees, housing, work, archive records, and AI-generated fictional dog portraits | Demonstrate product behavior | Shared baseline PostgreSQL rows and static WebP assets | Public demo visitors and hosting providers | Versioned product artifact. It contains no real kennel, customer, person, or dog data. |

## Browser storage audit

- Cookie: `ht_demo_session`, strictly necessary, random opaque value, `HttpOnly`,
  `SameSite=Lax`, `Secure` in production, path `/api/v1`, expiry aligned to the
  configured workspace TTL.
- `localStorage`: none.
- `sessionStorage`: none.
- IndexedDB: none.
- Analytics, advertising, marketing, and fingerprinting identifiers: none.

The cookie is not a consent mechanism or marketing identifier. No consent banner is
shown because the only browser storage is required to isolate the interactive demo.
This decision must be revisited if non-essential storage is introduced.

## Code and configuration references

- Workspace lifecycle and copy-on-write: `backend/app/services/demo_workspace_service.py`
- Cookie dependency and APIs: `backend/app/api/dependencies/demo_workspace.py` and
  `backend/app/api/routes/demo_workspace.py`
- Public metadata: privacy fields in `backend/app/core/config.py`
- Contact delivery: `backend/app/services/contact_delivery.py`
- Baseline-only checksum: `backend/app/demo/semantic.py`
- Browser initialization/reset: `frontend/src/app/core/api/demo-session.service.ts`
  and `frontend/src/app/layout/demo-shell/`

Final provider, transfer, mailbox, and log-retention facts are live-deployment
acceptance items for P12B. P12A startup validation refuses placeholder controller,
contact, and hosting-region values. The VPS/hosting location alone does not determine the
controller's competent supervisory authority.
